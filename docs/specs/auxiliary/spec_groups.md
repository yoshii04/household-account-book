# 仕様：C-6 グループ管理

## 概要

グループは取引を「人別」「目的別」などの軸で分類するためのマスタデータである。取引入力時にグループを選択することで、カテゴリ×グループのマトリックスレポートなどで多軸集計が可能になる。グループの作成・変更はデータ投入時（インポート・初期設定）で行われ、現状 UI からの管理機能は提供しない。

---

## 対象画面・エンドポイント

| 種別 | パス | 説明 |
|------|------|------|
| API | `GET /api/v1/groups` | グループ一覧取得（read-only） |

> 画面（HTML ページ）は存在しない。グループは取引入力フォーム・取引一覧フィルター・レポート等の他機能から参照される。

---

## 対象ファイル

- `backend/app/routers/groups.py` — API ルーター（`GET /api/v1/groups` の定義）
- `backend/app/models/group.py` — ORM モデル（`Group` クラス）
- `backend/app/schemas/group.py` — Pydantic スキーマ（`GroupOut`）

---

## データモデル

### groups テーブル

| カラム | 型 | 制約 | 説明 |
|--------|-----|------|------|
| `id` | Integer | PK、autoincrement | 内部 ID |
| `code` | String(50) | NOT NULL、UNIQUE | グループコード（例: `20_太郎`、`10_必須(通常)`） |
| `name` | String(100) | NOT NULL | グループ表示名 |
| `sort_order` | Integer | NOT NULL、default=0 | 表示順 |
| `created_at` | DateTime with timezone | — | 作成日時 |

### 関連テーブル

- `transactions.group_id` — `groups.id` を参照する外部キー（nullable）
  - 1 つの取引は 0 または 1 つのグループに属する
  - グループ未設定の取引も許容される

---

## 機能仕様

### グループ一覧取得（GET /api/v1/groups）

- 全グループを `sort_order` 昇順、`code` 昇順の優先度でソートして返す
- レスポンス形式: `list[GroupOut]`
  - `id` (Integer)
  - `code` (String) — グループコード
  - `name` (String) — グループ表示名
  - `sort_order` (Integer) — 表示順
- フィルタリング・ページングなし（全件返却）

### グループコードの命名規則

- `code` フィールドは数値プレフィックス（例: `10_`、`20_`）を持つことが多い
- 数値プレフィックスは表示順を視覚的に示す役割を持ち、`sort_order` フィールドと連動して管理される
- 例:
  - `10_必須(通常)` — 必須の通常費用グループ
  - `20_太郎` — 個人別グループ

### グループの作成・変更

- グループの追加・編集・削除は UI から行えない
- グループはデータ投入時（インポート処理・初期 DB 投入）に作成される
- 公開 API は `GET /api/v1/groups` のみ

### グループの利用箇所

| 利用箇所 | 用途 |
|----------|------|
| 取引入力フォーム（`/transactions/new`） | グループ選択肢として表示 |
| 取引編集フォーム（`/transactions/{id}/edit`） | グループ選択肢として表示 |
| 取引一覧（`/transactions`） | グループ絞り込みフィルター |
| カテゴリ×グループ マトリックスレポート（`/reports/matrix`） | 列軸としてグループを使用 |
| エクスポート（Excel、Actual.TXT） | グループ情報を出力列として含む |

---

## 実装上の注意点

- グループ管理には専用画面が存在しないため、Jinja2 テンプレートの記述ルール（`tojson`、シングルクォート属性等）は本機能には適用外である
- ソート順は DB クエリレベルで `sort_order` 昇順 → `code` 昇順の優先度で適用される
- グループの取得のみ API で公開されており、作成・更新・削除は UI からは行えない。DB への直接投入またはマイグレーションによる初期データ投入で管理する
